XODUS P0 — Architecture and Workflow

WealthAI Labs proof of concept: migrating acquired-firm wealth-management data (CoreCap source, Simplicity target) into a canonical model with lineage, explainable recommendations and human approval.

Scope: Account, Client, Household. Direction: source to canonical only. Agents recommend; deterministic services check; authenticated humans approve. Keep this page in step with the code (routes in ui/app.py, roles in ui/role_policy.py).

Layers

Roles (personas)

PersonaCan
Platform AdminEverything, including demo load and workflow replay.
Migration AnalystSet up a migration, choose scope, upload and profile sources, confirm file classification, generate and approve mappings and transformations, answer information requests, raise canonical change requests.
Validation SpecialistValidation-side evaluation after transformation rules exist (data plane). Read-only on setup and discovery.
Domain SME / Data StewardOwns canonical-model changes: updates the kernel and decides change requests; also answers business-definition questions.

A user may hold several personas (a normal user: Analyst and Validation Specialist; the SME holds both plus the SME persona) and acts under the persona selected at /persona-selection. Forms a persona cannot use are hidden, and the server enforces the same rules.

Workflow

1

Sign in and choose a persona

/login · /persona-selection
Reviewer identity always comes from the authenticated session.
2

Migration setup

/migration-setup · POST /api/migration/setup · admin demo load POST /api/demo/load
Name the migration, pick source and target, select entities (Account, Client, Household), attach knowledge references.
3

Source discovery

/entity-sample-files · POST /api/entities/upload-sample-file · confirm-inference / confirm-entity
Upload CSV, TSV, XLSX, XLSM, XLS or JSON files. Profiling and entity inference propose a classification with evidence; an analyst confirms or rejects it. Relationship files are deferred rather than forced into a master entity.
4

Mapping recommendations

/agent-pipeline · POST /api/entities/map-approved-files · GET /api/mapping-suggestions
Agents propose source-to-canonical field mappings with rationale, confidence and lineage. Missing definitions become information requests (/api/mapping-gaps/{id}/response).
5

Human review and approval

POST /api/mapping-suggestions/{id}/review · approve-entity
Analysts approve, reject or override. Only registered transformations are accepted; bulk approval is atomic. Approvals persist and survive restart.
6

Canonical change requests

/canonical-changes
An analyst raises a request (entity, field, change type, reason); the Domain SME approves, rejects or defers with a note. Approved requests are backlog only and do not edit the canonical model automatically.
7

Reconciliation view and lineage

/reconciliation · GET /api/pilot/{entity}/lineage
Review completeness, keys, relationships and data-quality exceptions with source-to-canonical lineage.
